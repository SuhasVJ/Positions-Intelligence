# Positions Intelligence

A lightweight Python service for retrieving and monitoring today's Zerodha Kite positions.

## Features (M1)
- Read-only Kite Connect integration
- Today's day positions and P&L summary
- FastAPI REST endpoints
- WebSocket snapshots pushed to connected clients
- Minimal browser UI served by the API
- No database or order-placement functionality

## Requirements
- Python 3.10+
- Zerodha Kite Connect API key and API secret
- Kite Connect app redirect URL configured to: `http://127.0.0.1:8000/`

## Run locally (Windows PowerShell)

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Edit `.env` and set `KITE_API_KEY` and `KITE_API_SECRET`. Keep the secret private.

Start the service:

```powershell
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Open [http://127.0.0.1:8000](http://127.0.0.1:8000), select **Connect Kite**, and complete Zerodha login. The configured Kite Connect redirect URL must point to the root URL above. The app exchanges the returned request token for an access token in memory.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/health` | Service and Kite session status |
| GET | `/api/auth/login` | Get Kite login URL |
| POST | `/api/auth/session` | Exchange request token |
| GET | `/api/positions/today` | Fetch today's day positions and P&L |
| WS | `/ws/positions` | Receive refreshed position snapshots |

Interactive API documentation: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

## Update behaviour
The WebSocket pushes a fresh positions snapshot every `POSITION_REFRESH_SECONDS` (default 5 seconds) while at least one client is connected. This polls Kite's positions endpoint; it is not a KiteTicker market-tick stream. It is intentionally sufficient for the first milestone. Live quote-driven P&L can be added separately.

## Security
- Never commit `.env`, API secrets, request tokens, or access tokens.
- The service is read-only and does not place, modify, or cancel orders.
- The access token generated by login is held in process memory and must be renewed through login when the process restarts.
- Restrict CORS and add proper authentication before exposing this service beyond localhost.
